# powerful2026 Shopifyテーマのカスタマイズ記録

## 目的
- 顧客からのテーマ調査やテーマ修正の案件に対して、AI(Claude Code)を活用して対応する。自然言語でAIに依頼し、調査やコード修正を進める。
- Shopifyテーマのカスタマイズ記録を取り、顧客からのカスタマイズ案件に備える。エンジニア向けの説明のため注意。

## 開発環境

- VSCode

## 基本方針
- 顧客のコードを修正する案件を想定し、**正は Shopify の編集用(edit)テーマ**とする。
- GitHub は変更の記録とレビュー用とする。`main` は Shopify より遅れていることがある。
- Shopify 側の変更を、破棄したり巻き戻したりしない。
- 公開中(ライブ)テーマへの反映は、このフローの対象外とする。
- Shopify CLI の操作はユーザーが行い、Claude Code は実行しない。
- コミット・プッシュ・PR作成は、ユーザーが依頼したときだけ Claude Code が行う。
- Issue は使わない。

## 開発の進め方
テーマの調査・修正は、自然言語で Claude Code に依頼して進める。

| 手順 | 担当 | 内容 |
| ---- | ---- | ---- |
| 1 | ユーザー | 作業前の準備(下記「開発手順1」)。`main` に切り替え、`theme pull` で Shopify 上の最新の編集用テーマを `main` の作業ツリーに展開する。`git pull` は行わない |
| 2 | ユーザー | Claude Code にテーマ調査・テーマ修正を依頼する |
| 3 | Claude Code | 開発ブランチを作成して、調査・コード修正を行う。修正後は変更内容を報告して止まる |
| 4 | ユーザー | プレビューで確認する(下記「開発手順2」)。修正が必要なら、Claude Code に伝えて 3 に戻る |
| 5 | ユーザー | `theme push` で編集用テーマへ反映して、顧客に確認してもらう(下記「開発手順3」)。修正が必要なら、Claude Code に伝えて 3 に戻る |
| 6 | ユーザー → Claude Code | Shopify への反映が確定した後に、コミット・プッシュ・PR作成を依頼する。開発履歴の追記案を確認してもらい、同じコミットに含める |
| 7 | ユーザー | GitHub 上で PR をマージし、リモートの開発ブランチを削除する |
| 8 | ユーザー → Claude Code | ローカルの開発ブランチの削除を依頼する |
| 9 | ユーザー | Shopify からログアウトする |

- Shopify への反映(手順5)を、GitHub への記録(手順6)より先に行う。これにより、`main` は Shopify に反映済みの内容の記録になる。
- 調査のみの依頼(コードを変更しない)では、開発ブランチ・コミット・PR は作らず、調査結果の報告で終える。調査は、`theme pull` 後の状態(Shopify の状態)を正として行う。
- ストア側の情報(テーマエディタの設定、アプリ、エラー内容、再現 URL など)が必要な場合は、依頼時にユーザーが Claude Code に伝える。
- 1つの依頼につき、1つのブランチ、1つの PR とする。前の PR がマージされてから、次の依頼を行う。

## 開発手順
- Shopify上でのテーマ複製(編集用(edit)と保存用(backup)の作成)は、顧客が行う。ユーザーは、顧客が複製した編集用テーマを `shopify theme pull` でプルする
- WSL上で作業を行う
- Shopify CLI のコマンドは、ユーザーが実行する

### 開発手順1 作業前の準備
`git pull` は行わない。作業のたびに、`theme pull` で Shopify 上の最新の編集用テーマを `main` の作業ツリーに展開する。

```bash
## mainに切り替え
$ git checkout main

## ログイン
$ shopify auth login

## テーマの一覧 ※テーマIDを確認
$ shopify theme list --store powerful2026.myshopify.com

## 過去のプレビュー用テーマの削除
$ shopify theme delete --theme テーマID --store powerful2026.myshopify.com

## 編集用テーマのプル ※Shopifyの内容でローカルのテーマファイルが上書きされる
$ shopify theme pull --theme テーマID --store powerful2026.myshopify.com
```

- `theme pull` で展開された Shopify の内容は、`main` との差分として未コミットで残る。Claude Code は、この差分の確認や報告を行わない。差分は、今回の PR に含まれる。

### 開発手順2 プレビュー確認
```bash
## ローカルのテーマをプレビュー ※--themeは付けない(要確認)
$ shopify theme dev --store powerful2026.myshopify.com
```

- `--theme` を付けると、指定した編集用テーマ(正)を、ローカルの内容で直接書き換える可能性があるため、付けない。この挙動は要確認。
- プレビュー用に作られた開発用テーマは、手順1の「過去のプレビュー用テーマの削除」で整理する。

### 開発手順3 Shopifyへの反映
```bash
## 変更したファイルだけを編集用テーマへ反映 ※--onlyの書式は要確認
$ shopify theme push --theme テーマID --store powerful2026.myshopify.com --only sections/変更したファイル.liquid

## ログアウト
$ shopify auth logout
```

- 全ファイルを `push` すると、`theme pull` の後に Shopify 側で行われた変更(顧客やテーマエディタによる変更)を上書きするおそれがある。そのため、変更したファイルだけを反映する。
- 反映後に顧客に確認してもらい、修正が必要な場合は、Claude Code に伝えて修正し、再度プレビューと反映を行う。

### Git 操作 (Claude Code が実施)
Claude Code は次の操作を行う。コミット・プッシュ・PR作成は、ユーザーの依頼があったときだけ行う。

- 作業開始時: `main` の作業ツリーから、開発ブランチ `feature/英語の短い名前` を作成する。`git pull` は行わない
- 依頼時: ファイルを指定してステージングし、コミット・プッシュ・PR作成を行う。`theme pull` で展開された Shopify の内容との差分も、同じ PR に含まれる
- 依頼時: `main` をプルした後、ローカルの開発ブランチを `git branch -d` で削除し、その後に `git fetch --prune origin` でリモート追跡参照を整理する(順序を逆にすると、squash マージ済みのブランチは `-d` で削除できない)

リモートの開発ブランチの削除は、PR マージ後にユーザーが GitHub 上で行う。
